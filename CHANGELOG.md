# @gener8v/graph-generator

## 0.1.0

### Added

- **Added:** the issue code `too_few_ticks`. A tick spacing that leaves fewer than two ticks inside an axis range is rejected at the axis's `tickSpacing`, and the message names a spacing that fits. For example, a number line from 1 to 9 with a tick spacing of 10 is rejected. An axis without a tick spacing is not affected.
- **Added:** the `cube` type, as `<CubeGraph>` and the `./cube` entry. A cube is drawn from its edge length in the same isometric view as the other solids, with all twelve edges the same drawn length. The three hidden edges are dashed or left out. You can label one edge, or the three visible edges that meet at the front corner, with the length and unit or your own text.
- **Added:** cube edge labels are placed the same way in every JavaScript engine, so server-rendered cubes hydrate in Safari.
- **Added:** the `cylinder` type, as `<CylinderGraph>` and the `./cylinder` entry. An upright cylinder is drawn to scale from its radius or diameter and its height, in the same isometric view as the other solids. The hidden half of the base is dashed or left out. You can draw and label the radius or diameter on the top face, and label the height beside the side, with the value and unit or your own text. The circle and the cylinder share the terms `radius`, `diameter`, `showRadius`, `showDiameter`, `labelRadius`, `labelDiameter`, `radiusLabelText` and `diameterLabelText`.
- **Added:** the text alternative of a number line or an x,y graph states the default tick spacing exactly as drawn, so a default of 0.005 is stated as 0.005, not rounded.
- **Added:** the `graph-generator` command. `graph-generator export <file.json> [--out <file.tsx>] [--name <Name>]` reads a description file and writes the component file that `exportSource` produces. The default output is `<Name>.tsx` next to the description. For an invalid description it prints the first 20 issues and writes nothing. It exits with 0 when the file is written, 1 when the description or a file cannot be used, and 2 for an invalid command line. It runs on Node.js 22 and later without React and makes no network requests.
- **Added:** `exportSource(description, { componentName? })` from `./export`. It turns a valid description into the source of one standalone React component file (`.tsx`). The component depends only on React, takes no props, uses no hooks and renders the same markup as the package's component. The file opens with a comment that names the package version and contains the description. Pictograph images are embedded with their license notice. For an invalid description, or a component name that is not a PascalCase identifier, it returns the issues and no source. A valid result also includes `componentName`, the name the component was given.
- **Added:** the model tool in `./tool`. `graphTool` is a provider-neutral tool definition: `generate_graph`, a description and the generated strict tool schema. `handleGraphToolCall(input)` takes a tool call's input as an object or JSON text, treats `null` as "not given" and validates the description. It never throws. It returns `{ ok: true, description, provenance, textAlternative, summary }` or `{ ok: false, issues, summary }`. `summary` is plain text to send back to the model: the graph type and its text alternative, or the first 20 issues, numbered. JSON text longer than `TOOL_INPUT_LIMIT` (2,000,000 characters) is refused without being parsed. The text alternative in a result stops after `TEXT_ALTERNATIVE_LIMIT` (4,000) characters. Supported: Anthropic `input_schema` without `strict`, OpenAI `strict: true` and Gemini `parametersJsonSchema`. Not supported: Anthropic `strict: true` and Gemini `parameters`.
- **Added:** the `square` type, as `<SquareGraph>` and the `./square` entry. A square is drawn to scale from its side length. You can label one side or all four (with the length and unit, or your own text) and add right-angle marks.
- **Added:** the `triangle` type, as `<TriangleGraph>` and the `./triangle` entry. A triangle is drawn to scale from three sides, two sides and the angle between them, two angles and a side, or its three vertices. It stands on its first given side, or keeps the positions of its vertices. You can label sides, angles and vertices (with the value and unit, degrees, or your own text). A labeled 90° angle gets a right-angle mark. The `labelSides` description covers both the square and the triangle.
- **Added:** triangles, rulers, axes and cubes do not depend on the last digit of the engine's math functions, so the server and every browser draw them the same way and server-rendered graphs hydrate. This covers whether a triangle's label below its bottom side fits beside the side, how many arc pieces an angle that is a multiple of 15° gets, how a ruler mark's width is rounded and how an axis tick's end is rounded.
- **Added:** a unit that contains a quotation mark is quoted in text alternatives, and a pictograph states such a unit once, in its key, not after every value. A unit such as `votes, “Fish” is 40` cannot add entries that look like the package's own.
- **Added:** an x,y graph picks a coarser default tick spacing on a narrow or flat plot, so tick labels do not run together. For example, x from -2 to 2 beside a y-axis from -100 to 100 is ticked every 1, not every 0.5. The text alternative states the spacing drawn. A `tickSpacing` you supply is used as given.
- **Added:** the `xyz-graph` type, as `<XyzGraph>` and the `./xyz-graph` entry. A three-dimensional coordinate graph is drawn in the same isometric view as cubes and cylinders, with three labeled axes, plotted points and optional guide lines to the x,y plane.

### Changed

- **Changed:** the published descriptions of the `x` and `y` coordinate terms cover any point: a plotted point, the end of a segment or a vertex of a triangle. Their meaning and accepted values on x,y and x,y,z graphs are the same.
