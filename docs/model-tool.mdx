# Model tool

`@gener8v/graph-generator/tool` lets a language model draw graphs. It needs Node.js 22 or later and
no React. The package calls no model, makes no network requests and does not depend on any
provider's software.

- `graphTool` is a provider-neutral tool definition: a `name` (`generate_graph`), a plain-English
  `description` and an `inputSchema` (JSON Schema). Put these three values in your provider's
  request.
- `handleGraphToolCall(input)` takes a call's input as an object or as JSON text. It never throws.

The model sends the description in `graph`, with `null` for each value it leaves out:

```ts
{ graph: { type: "circle", radius: 3, diameter: null, circumference: null, showRadius: true /* ... */ } }
```

The handler returns one of these:

- `{ ok: true, description, provenance, textAlternative, summary }`. Pass `description` to `Graph`
  or `exportSource`.
- `{ ok: false, issues, summary }`. `issues` lists every problem, with paths into the input such as
  `/graph/radius`.

`summary` is plain text. On success it gives the graph type and the text alternative:

{/* sample: tool-summary-ok */}

```text
The circle was produced.
Text alternative: A circle with radius 3.
```

On failure it lists the first <Limit name="TOOL_SUMMARY_ISSUES" /> issues, numbered, with path and
message, and a count of the rest. The model can fix them and call the tool again:

{/* sample: tool-summary-failed */}

```text
The graph was not produced: 1 issue. Fix it and call generate_graph again with {"graph": <the description>}.
1. /graph/radius: radius must be a number between 0.001 and 1000000; got -3.
```

## Handling the result

- **Send `summary` back, not `issues`.** Use `summary` as the tool result. Do not send `issues` or
  the whole result. `issues` is complete and can run to megabytes for a large invalid input.
- **The text comes from the model.** `summary`, `textAlternative` and the text values in
  `description` (titles, labels, names) contain text the model wrote. The only change is that
  control characters are removed. Escape this text for HTML or Markdown, never insert it as markup,
  and treat it as data, not instructions.
- **`internal_error` is a bug in the package**, not a problem with the model's input. Please report
  it with the package version and the input.

## With a provider

The snippets below use each provider's own SDK client (`client` or `ai`), which you install and set
up yourself. Only `graphTool` and `handleGraphToolCall` come from this package:

```ts
import { graphTool, handleGraphToolCall } from "@gener8v/graph-generator/tool";
```

`inputSchema` is frozen. Pass `structuredClone(graphTool.inputSchema)` to SDKs whose types expect a
mutable object.

### Anthropic

The Messages API, with the SDK `@anthropic-ai/sdk`:

```ts
const response = await client.messages.create({
  model, // your model
  max_tokens: 16000,
  tools: [{ name: graphTool.name, description: graphTool.description, input_schema: structuredClone(graphTool.inputSchema) }],
  messages,
});
for (const block of response.content) {
  if (block.type !== "tool_use" || block.name !== graphTool.name) continue;
  const result = handleGraphToolCall(block.input);
  // Send back: { type: "tool_result", tool_use_id: block.id, content: result.summary, is_error: !result.ok }
}
```

### OpenAI

The Responses API in strict mode, with the SDK `openai`:

```ts
const response = await client.responses.create({
  model, // your model
  input,
  tools: [{ type: "function", name: graphTool.name, description: graphTool.description, parameters: structuredClone(graphTool.inputSchema), strict: true }],
});
for (const item of response.output) {
  if (item.type !== "function_call" || item.name !== graphTool.name) continue;
  const result = handleGraphToolCall(item.arguments); // JSON text
  // Send back: { type: "function_call_output", call_id: item.call_id, output: result.summary }
}
```

### Gemini

The Gemini API with `parametersJsonSchema`, with the SDK `@google/genai`:

```ts
const response = await ai.models.generateContent({
  model, // your model
  contents,
  config: {
    tools: [{ functionDeclarations: [{ name: graphTool.name, description: graphTool.description, parametersJsonSchema: structuredClone(graphTool.inputSchema) }] }],
  },
});
for (const call of response.functionCalls ?? []) {
  if (call.name !== graphTool.name) continue;
  const result = handleGraphToolCall(call.args);
  // Send back a functionResponse part: { name: call.name, response: { result: result.summary } }
}
```

### Without an SDK

Each request is plain JSON, so you can also use your own HTTP client. Put the tool in the request
body like this:

- Anthropic: `{ name, description, input_schema }`.
- OpenAI Responses: `{ type: "function", name, description, parameters, strict: true }`.
- Gemini: `{ functionDeclarations: [{ name, description, parametersJsonSchema }] }` in `tools`.

Each takes `graphTool.name`, `graphTool.description` and `graphTool.inputSchema`.

## Supported modes

The schema is tested against each provider's documented rules as of 2026-11-04:

- Anthropic `input_schema` without `strict`.
- OpenAI function calling with `strict: true`, in Chat Completions and Responses.
- Gemini API `parametersJsonSchema`.

Not supported:

- Anthropic `strict: true`. Its subset rejects `maxLength`, `minimum`, `maximum` and `maxItems`, and
  allows at most 16 parameters with a union type. This schema has about 140.
- Gemini `parameters`, and Vertex AI function declarations. They use an OpenAPI subset with
  `nullable` instead of type arrays and no `additionalProperties`.

Some keywords, such as `maxLength` in OpenAI strict mode, are not documented for a supported mode.
The handler validates every call either way.

## Limits

- JSON text longer than `TOOL_INPUT_LIMIT` (<Limit name="TOOL_INPUT_LIMIT" /> characters, counted
  as UTF-16 code units) is refused as `too_large` without being parsed. The largest valid
  description, with every optional value sent as `null`, is about 876,000 characters as compact
  JSON and about 1,019,000 with two-space indentation. Text that escapes every non-ASCII character
  as `\u` can be several times longer and go over the limit.
- An input object can hold at most <Limit name="DESCRIPTION_VALUE_LIMIT" /> keys, the same limit
  as for values in a description.
- `textAlternative`, and the text alternative in `summary`, stop after `TEXT_ALTERNATIVE_LIMIT`
  (<Limit name="TEXT_ALTERNATIVE_LIMIT" />) characters and end in "…".
  The largest graphs need more than 500,000 characters. For the full text, call
  `describe(description)` from `@gener8v/graph-generator/core`.
- Text that is not JSON gets an `invalid_json` issue. The handler does not search it for JSON, so
  JSON inside prose or a code fence is rejected.
- Text in the description must follow the plain-text policy on the **Vocabulary** page. A model
  cannot slip hidden characters, such as tag characters, into a title or label.
