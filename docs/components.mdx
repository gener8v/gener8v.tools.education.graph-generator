# @gener8v/graph-generator

Turn one JSON description of a math graph or figure into a React component, for lessons,
worksheets and assessments. Every graph type uses the same kind of JSON description. You can draw
it as a React component, export it as a standalone component file, or give it to a language model
as a tool.

The pages on this site:

- **Components** (this page): drawing a description with React.
- **Graph types**: each graph type with a working example and the inputs it accepts.
- **Vocabulary**: every term, the limits, the plain-text policy and how descriptions are checked.
- **Issue codes**: what an invalid description reports, and how to print it safely.
- **Source export**: a description as a standalone `.tsx` file, from code or the command line.
- **Model tool**: letting a language model draw graphs.

The package makes no network requests and collects no data. This site loads nothing from outside
its own files.

## Install

You need React 18 or 19. The entry points that do not render (`@gener8v/graph-generator/core`,
`/tool` and `/export`) need Node.js 22 or later and no React.

```sh
npm install @gener8v/graph-generator
```

## Draw a graph

A description is a JSON object with a `type` and the values that type accepts:

```json
{
  "type": "circle",
  "radius": 3,
  "showRadius": true,
  "labelRadius": true,
  "unit": "cm",
  "title": "Find the diameter"
}
```

Pass it to `Graph`. It draws any graph type as an accessible SVG that scales to fit its container:

```tsx
import { Graph } from "@gener8v/graph-generator";

export function Figure({ description }: { description: unknown }) {
  return <Graph description={description} />;
}
```

`Graph` takes these props:

- `description`: any value. A valid description is drawn. An invalid one renders the fallback.
- `textAlternative`: the graph's accessible name. If it is missing or blank, the package writes one
  from the description.
- `fallback`: what to render for an invalid description. `"placeholder"` (the default) shows a box
  that lists the issues. `"none"` renders nothing. A function receives every issue and returns what
  to render.

`Graph` never throws because of a bad description. It has no hooks, state or effects, so it works
as a React Server Component.

## One graph type only

Each graph type also has its own component and entry point, such as `CircleGraph` from
`@gener8v/graph-generator/circle`. It takes the same props. A per-type entry contains only that
type's code, so a page that draws only circles does not load the other types. A description of any
other type is invalid for it.

```tsx
import { CircleGraph } from "@gener8v/graph-generator/circle";

export function Circle({ description }: { description: unknown }) {
  return <CircleGraph description={description} />;
}
```

The entry points are `./circle`, `./square`, `./triangle`, `./cube`, `./cylinder`, `./number-line`,
`./ruler`, `./xy-graph`, `./xyz-graph`, `./line-graph`, `./bar-graph` and `./pictograph`.

## Invalid descriptions

Use a fallback function to get the issues in your code. It runs during render, so it must not have
side effects. An issue's `path` contains the caller's keys exactly as given, including any line
breaks or text-direction characters. Print issues with `formatIssue` from
`@gener8v/graph-generator/core`, never with `issue.path` directly:

```tsx
import { Graph } from "@gener8v/graph-generator";
import { formatIssue } from "@gener8v/graph-generator/core";

export function Figure({ description }: { description: unknown }) {
  return (
    <Graph
      description={description}
      fallback={(issues) => (
        <ul>
          {issues.map((issue, index) => (
            <li key={index}>{formatIssue(issue)}</li>
          ))}
        </ul>
      )}
    />
  );
}
```

To log the issues or act on them, call `validate` yourself, outside render:

```ts
import { formatIssue, validate } from "@gener8v/graph-generator/core";

const result = validate(description);
if (!result.valid) {
  for (const issue of result.issues) console.warn(formatIssue(issue));
}
```

**Issue codes** lists every code and what it means.

## Validation on every render

The components are pure and keep nothing between renders, so they validate the description every
time. With a large description that re-renders often, such as an x,y graph with many points, that
work adds up. Keep the element stable, for example by memoizing it in your own client component:

```tsx
"use client";
import { useMemo } from "react";
import { Graph } from "@gener8v/graph-generator";

export function Figure({ description }: { description: unknown }) {
  // Validated again only when the description changes.
  return useMemo(() => <Graph description={description} />, [description]);
}
```

Or call `createGraph` once. It never throws. It returns `{ ok: true, description, provenance, scene }`
(the normalized description, which values were derived, and the drawing) or `{ ok: false, issues }`.

```ts
import { createGraph } from "@gener8v/graph-generator";
import { formatIssue } from "@gener8v/graph-generator/core";

const result = createGraph(description);
if (!result.ok) {
  for (const issue of result.issues) console.warn(formatIssue(issue));
}
```

## Servers

The validator limits its own work, but it still reads the whole input object. If your server
draws descriptions from requests, keep a request-body size limit. The largest valid description is
about 1.6 MB as JSON, so a few megabytes is enough.

## Styling

Graphs are inline SVG and take their look from the package, not from your page. One page rule can
still change what a graph shows. A pictograph draws a fraction of a picture with a nested `svg`
that relies on the browser default `overflow: hidden`. If you set `overflow: visible` on every
`svg`, a value of 2.5 pictures shows as 3. Scope that rule away from the graphs, for example with
`svg:not(.your-icon-class)`.
