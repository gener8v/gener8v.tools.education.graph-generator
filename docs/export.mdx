# Source export

Source export turns a description into one standalone React component, a `.tsx` file. The file
depends only on React, takes no props, uses no hooks and renders the same markup as the package's
component. Use it to add a figure to a project that does not install this package, or to freeze a
figure so package updates do not change it.

## From code

`exportSource(description, options)` from `@gener8v/graph-generator/export` needs Node.js 22 or later
and no React. It uses the same validator as the components, so it accepts exactly the descriptions
they draw.

```json
{
  "type": "square",
  "sideLength": 4,
  "unit": "cm",
  "labelSides": "all",
  "title": "Aire du carré"
}
```

```ts
import { writeFileSync } from "node:fs";
import { formatIssue } from "@gener8v/graph-generator/core";
import { exportSource } from "@gener8v/graph-generator/export";

const result = exportSource(description, { componentName: "SquareFigure" });
if (result.ok) {
  writeFileSync(`${result.componentName}.tsx`, result.source);
} else {
  for (const issue of result.issues) console.error(formatIssue(issue));
}
```

- `componentName` is optional and must be a PascalCase identifier. The default comes from the
  graph type, such as `SquareGraph`.
- The result is `{ ok: true, source, componentName }`, or `{ ok: false, issues }` with every issue
  in the description and in `componentName`.
- It never throws. The same description and package version always give the same text.

The file starts with a comment that names the package and version and contains the description.
The component follows. Here it is shortened, and `<version>` stands for the package version:

{/* sample: export-square */}

```tsx
/*
 * SquareFigure: a square exported by \u0040gener8v/graph-generator <version> with exportSource.
 * It depends on React alone, through the automatic JSX runtime, takes no props and uses no hooks.
 * To change the graph, export the description again rather than editing the drawing.
 *
 * Description:
 * {
 *   "type": "square",
 *   "sideLength": 4,
 *   "unit": "cm",
 *   "labelSides": "all",
 *   "title": "Aire du carr\u00e9"
 * }
 */
export function SquareFigure() {
  return (
    <svg role={"img"} aria-label={"A square titled \u201cAire du carr\u00e9\u201d with side length 4 cm. All four sides are labeled."} viewBox={"0 0 400 315.2"} width={"100%"}>
      <title>{"A square titled \u201cAire du carr\u00e9\u201d with side length 4 cm. All four sides are labeled."}</title>
      ...
    </svg>
  );
}
```

The `@` and the accented letter are written as escapes because the file is ASCII only (see below).
The text still renders as described.

To change the figure, change the description and export it again. Do not edit the drawing.

## From the command line

`graph-generator export` writes a saved description out as a component file. It needs Node.js 22
or later, not React, and makes no network requests.

Always run it with the full package name. The bare command name can run a different
package from the registry.

```sh
npm install --save-dev @gener8v/graph-generator
npx @gener8v/graph-generator export square.json                 # writes SquareGraph.tsx beside it
npx @gener8v/graph-generator export square.json --out src/SquareFigure.tsx --name SquareFigure
```

- `--out <file.tsx>` sets the output file. The default is `<Name>.tsx` next to the description.
  It cannot be the description file. Without `--out`, Windows device names such as `CON` or `NUL`
  are refused.
- `--name <Name>` sets the component name, a PascalCase identifier. The default comes from the
  graph type.
- An existing output file is replaced. The command writes a temporary file and renames it, so a
  link at the output path is replaced, not followed.
- The description must be a regular file of at most <Limit name="MAX_INPUT_BYTES" />. The largest
  valid description is about 1.6 MB.
- For an invalid description it prints the first <Limit name="MAX_ISSUES_PRINTED" /> issues with
  `formatIssue` and a count of the rest, and writes nothing.
- Exit status: 0 when the file is written. 1 when the description is invalid or a file cannot be
  read or written. 2 when the command line is invalid or the output is the description file.

The output is the same text that `exportSource` returns.

## What the file needs

- **React's automatic JSX runtime** (React 17 or later). The file has no `import React`, so the
  classic transform (`"jsx": "react"` in `tsconfig.json`) fails with `React is not defined`. Use
  `"jsx": "react-jsx"` or your framework's default.
- **Nothing else.** It imports nothing, not even this package.

## ASCII only

Every exported file is ASCII only. Non-ASCII text such as "é" or "“" is written as `\u` escapes,
and so is every `@`. The text still renders exactly as described. No invisible, line-breaking or
reordering character can hide in the file. Text from a description also cannot form a comment
directive (these start with `@`) that a compiler or tool would read.

## Pictures in a pictograph

A pictograph's picture is embedded in the file as a drawing, so the file needs no package or URL.
The header comment names each embedded drawing with its author and license, and includes the full
notice the license requires in every copy.
