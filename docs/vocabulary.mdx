# Vocabulary

A description is a JSON object. `type` names the graph type. The optional `version` names the
schema version it was written for. Every other key is a term from that type's vocabulary. The
tables on this page are built from `vocabulary.json`, which the package publishes as
`@gener8v/graph-generator/vocabulary.json`, so they always match what the package accepts.

```json
{
  "type": "number-line",
  "axis": { "min": 0, "max": 10, "tickSpacing": 1 },
  "points": [{ "value": 7, "label": "7" }],
  "title": "Plot 7"
}
```

## Limits

<LimitFacts />

- Each list has a maximum length, `maxItems`, shown in each type's input table below. A longer list
  is the issue `too_large`.
- Titles, labels and names are at most <Limit name="CALLER_TEXT_LIMIT" /> characters, and `unit` at
  most <Limit name="UNIT_TEXT_LIMIT" />. Characters are counted as code points, so an emoji counts
  once. Longer text is the issue `too_large`. It is never cut short to fit. Text within the limit
  can still be cut at the drawing's line caps, but the text alternative always gives it in full.
- A description with too many values gets one `too_large` issue for the whole description, and is
  not checked further.

## Plain-text policy

All text in a description is plain text. Validation rejects text that contains:

- Control characters, and the line and paragraph separators (U+2028, U+2029).
- Text-direction overrides and isolates, which reorder text.
- Invisible format characters, which hide text or carry hidden text. These are the soft hyphen,
  the Arabic letter mark, the Mongolian vowel separator, the zero-width space, direction marks,
  word joiners, invisible operators, the deprecated format characters, the byte-order mark, the
  interlinear annotation marks, tag characters (U+E0000 to U+E007F, which language models read as
  ASCII) and the supplementary variation selectors.
- Half of a surrogate pair on its own.

The zero-width joiner and non-joiner (U+200C, U+200D) and the emoji variation selectors (U+FE00 to
U+FE0F) are allowed, so emoji sequences work. Rejected text is the issue `wrong_kind`.

## Checking a description

`@gener8v/graph-generator/core` checks a description without drawing it:

- `validate(input)` never throws. It returns `{ valid: true, description, provenance }` (the
  normalized description, and which values were supplied or derived) or `{ valid: false, issues }`
  with every issue found.
- `normalize(input)` returns the normalized description: known terms only, derived values filled
  in, colors resolved. It throws if the input is invalid. Call `validate` to find out why.
- `describe(input)` returns the plain-text alternative that a screen reader reads. It also throws
  if the input is invalid.

```ts
import { describe, validate } from "@gener8v/graph-generator/core";

const result = validate(description);
if (result.valid) {
  console.log(describe(result.description));
}
```

For the circle on the Components page, it prints:

{/* sample: describe-circle */}

```text
A circle titled “Find the diameter” with radius 3 cm. Its radius is drawn.
```

## The JSON Schema and the validator

The package also publishes a JSON Schema, `@gener8v/graph-generator/schema.json`, for editors and
other tools. It describes the shape of a description but does not make every check:

- It applies the plain-text policy only to characters up to U+FFFF. Only `validate` rejects tag
  characters, supplementary variation selectors and lone surrogates.
- It does not check that values agree with each other, such as a radius and a diameter. The input
  tables list these cross-value checks for each type.

Use `validate`, not the schema, to check text from users or models. The schema and the validator
agree on the JSON form of a description. One difference: `validate` ignores a key whose value is
`undefined`, which JSON cannot hold, and a JSON Schema validator rejects it.
